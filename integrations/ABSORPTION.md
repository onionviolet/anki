Reference documentation was reviewed before implementation. Compatibility of optional third-party add-ons must be checked on the installed version; links are not a compatibility certification. Existing user-installed add-ons and their settings are preserved.

Repairs support exporting a version 1 JSON snapshot and importing a proposed `changes` mapping against that exact snapshot. This is the preferred path for externally prepared corrections: import opens a diff, and accepting performs one undoable collection operation. Protected fields and stale snapshots are rejected before writing. Files remain outside the repository.

The existing upstream simulator wrote missing memory-state metadata to cards while preparing a simulation. That path now computes metadata on local copies only; a Rust regression test and Python collection test protect the read-only contract. The comparison also passes zero additional unseen cards, avoiding double-counting the selected collection as hypothetical new intake.

## Optional integration routes and external gates

### Yomitan

The current Chrome profile had no Yomitan result in its Extensions inventory; no installed Yomitan version can be certified. The existing daily AnkiConnect add-on directory was inspected read-only, and its configuration advertises API v6. The actual runtime test used the fork's bundled v6 bridge pinned in [SOURCE.md](../qt/aqt/weibao/ankiconnect_vendor/SOURCE.md), not the daily server. The test exercised `version`, `modelFieldNames`, `canAddNotes` and `guiAddCards` over HTTP. `guiAddCards` filled the native Add Cards editor while note count remained unchanged; closing the draft did not save it. No credentials, personal notes or browser settings were changed.

[Official Yomitan setup](https://yomitan.wiki/anki/) provides deck/model selection and markers for expression, definition, sentence, page title and URL. The reviewed [AnkiConnect client at 67db60d](https://github.com/yomidevs/yomitan/blob/67db60ddc2cbd7b5172d777c117e3201d7ddff0f/ext/js/comm/anki-connect.js) calls `addNote` for its add action, so that button does not inherit the first-party preview/accept flow. A usable preview-preserving route is:

1. Look up the term in Yomitan and copy the term, selected definition and sentence as plain text into **Study tools → Capture** on the chosen deck/note type.
2. Paste the page URL/title into the source controls and select their destination field; select a local pronunciation file and its field when available.
3. Play the local audio, choose **Preview**, review the actual fields, then choose **Add previewed note**. Any edit requires another preview.

For browser draft producers that already create AnkiConnect note JSON, use `guiAddCards` instead of `addNote`, then review and click Add in the native editor. This is a tested API route, not a claim that current Yomitan exposes that switch. In isolated browser testing, use the separate 8779 endpoint and keep the daily extension configuration unchanged. Browser extension installation, dictionaries, origin permission and an actual lookup remain external gates because Yomitan is absent. The bridge compatibility result does not certify an absent extension or intercept its direct field writes.

### HyperTTS and local audio

HyperTTS is absent from the daily add-on inventory. The reviewed [MacOS service at 05007b9](https://github.com/Vocab-Apps/anki-hyper-tts/blob/05007b9a0982f18fd6e679ce651fe356074f1dbe/hypertts_addon/services/service_macos.py) uses macOS `say` and Anki's MP3 encoder; it is opt-in and marked free. The main add-on, provider UI, credentials and remote providers are not installed or enabled by this fork. Provider dependency availability is recorded in the runtime transcript; no missing dependency was installed.

The `integrations/local_speech.py` adapter exposes the installed-system-speech route without importing HyperTTS: `just local-speech 'Text to speak' /path/to/new.wav`. It generates PCM WAV, refuses an existing output path, and makes no provider request. Han text without Japanese kana defaults to `zh_CN`; other text uses the system voice. This is a Mandarin-specific assumption, not general language detection. Pass a language explicitly for Japanese, Cantonese, or other Han text, and for pinyin-only input. The optional recipe arguments are language, exact installed voice name, and rate in words per minute:

```sh
just local-speech '你好，世界。' /tmp/mandarin-preview.wav
just local-speech '你好，世界。' /tmp/taiwan-preview.wav zh_TW
just local-speech '你好，世界。' /tmp/mandarin-slow.wav zh_CN '' 140
just local-speech 'Text to speak' /tmp/system-preview.wav system
```

Reviewer TTS and local WAV generation share the Mandarin preference: Tingting/Tian-Tian for `zh_CN`, Meijia for `zh_TW`, and labeled Premium/Enhanced variants when installed. Explicit voice requests remain authoritative; an unavailable requested language or voice in the local adapter produces an error instead of a different-language recording. The adapter does not download voices. The earlier English sample was generated, played to completion, previewed and imported through Capture. Existing audio produced elsewhere, including an installed HyperTTS service, can use the same local-file route. Use **Choose local audio → Play audio → Preview → Add previewed note**. HyperTTS's own batch/realtime UI and provider-specific behavior remain external gates.

The Mandarin continuation generated `out/mandarin-tts-preview.wav` with this Mac's installed `Tingting (Chinese (China mainland))` voice. Python checks cover both macOS players' fallback/explicit-voice/region behavior and the local adapter's language selection and missing-language rejection. Listening acceptance is separate from generation and selection checks. The running daily profile's `Mandarin Merged` templates were separately backed up outside this repository and updated through AnkiConnect: exactly seven `zh_CN` TTS tags now request `Apple_Tingting_(Chinese_(China_mainland)),Apple_Ting-Ting`. Saved template HTML and CSS matched the planned changes exactly. No field text or scheduling operation was requested. This collection setting takes effect in the current app; the fork source change requires launching or installing the updated fork.
